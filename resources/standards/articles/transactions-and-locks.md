# Транзакции и блокировки

Транзакция нужна для атомарного изменения связанных данных. Держите в ней только действия, которые нельзя безопасно вынести наружу: блокировки остаются до завершения, а длительная транзакция удерживает ресурсы и задерживает конкурирующие операции.

Начало, фиксацию и отмену транзакции размещайте в одном методе. После начала транзакции выполняйте работу внутри единого блока обработки ошибок: при сбое сначала отмените транзакцию, затем выполняйте дополнительные действия. Если изменение объекта само создаёт необходимую транзакцию платформы, не добавляйте явную транзакцию без причины.

Подготовительные вычисления и чтение без блокировки по возможности выполните заранее. Для массовой обработки используйте ограниченные порции, чтобы не создавать одну длинную транзакцию.

**Проверка:** составьте список запросов и блокировок внутри транзакции; для каждого подтвердите, что ему необходима атомарность с записью.

Стандарт содержит сценарные исключения и уточнения; сверяйте полный текст с версией платформы и используемым видом приложения.

Источник: [Транзакции: правила использования, стандарт #std783](https://its.1c.ru/db/content/v8std/src/300/300/i8100783.htm).

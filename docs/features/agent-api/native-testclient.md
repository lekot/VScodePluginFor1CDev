# Нативное управление тест-клиентом 1С

## Назначение

`agent.forms.discover` на Windows находит локальные процессы `1cv8.exe`/`1cv8c.exe` только при наличии `/TESTCLIENT`, корректного `-TPort` и слушающего TCP-порта. Ответ содержит PID и порт, но не командную строку.

`agent.forms.launch` запускает локальный тонкий TestClient и подключает native-сессию. Передайте ровно один источник: `dbPath` каталога файловой базы с `1Cv8.1CD` или `infobaseId` записи файловой/серверной базы из Infobase Manager. Для серверной записи берутся пользователь и пароль из каталога/SecretStorage. Необязательные `platformPath`, `port` и `waitTimeoutMs` позволяют выбрать платформу, порт и ограничить общее время запуска и подключения (1000–120000 мс; по умолчанию 90000). После открытия TCP-порта команда повторяет native attach при временных отказах, пока не истечёт это время; в progress-сообщении указывает, что нужно подтвердить возможные диалоги 1С. При timeout ошибка объясняет, что клиент мог ожидать подтверждения, входа пользователя или окончания запуска. Без `port` система выделяет свободный локальный порт. Платформа выбирается без UI: явный `platformPath`, настройка расширения, версия/разрядность базы, затем уникальная наиболее новая подходящая установка; при неоднозначности запуск завершается ошибкой.

`agent.forms.start` остаётся отдельной командой подключения к уже запущенному тонкому клиенту, стартовавшему с `/TESTCLIENT -TPort <port>`. Поле `port` обязательно, `driver: "native"` можно указать явно, а `host` по умолчанию равен `127.0.0.1`; `platformVersion` необязателен. Действия формы могут менять данные открытой базы, поэтому подключайте подходящую тестовую базу и учитывайте побочные эффекты своих действий.

Опциональный end-to-end smoke в VS Code test host проходит `forms.discover → forms.launch → forms.native overview → forms.stop`. Он запускается только при наличии `TESTCLIENT_LIVE_DB_PATH` и `TESTCLIENT_LIVE_EXE`; без обеих переменных suite пропускается. После закрытия сессии smoke проверяет PID, executable, `/TESTCLIENT` и порт, затем завершает только процесс, который вернул его собственный `forms.launch`.

Все runtime-операции форм работают только с активным native TestClient. `forms.status` сообщает состояние подключения, `forms.stop` закрывает TCP-сокет, не останавливая сам клиент. Если запуск или подключение завершается ошибкой, Agent пытается остановить созданный процесс и возвращает PID, порт и статус очистки; при неподтверждённой остановке результат помечается `inDoubt`. `forms.shot` требует активную native-сессию; снимок окна доступен для локального TestClient на Windows и возвращает ошибку, если процесс или окно недоступно, окно неоднозначно либо клиент удалённый. Вызовы `forms.start` с `url`, `dbPath`, `platformPath` или `readyTimeoutMs` отклоняются.

## Native Agent/MCP API

Новый `agent.forms.native` и MCP tool `cdt_forms_native` используют обязательный `action` из дискриминированного набора:

- `overview` — активное окно и дерево доступных объектов формы;
- `commandInterface` — команды активного окна;
- `executeCommand` — запуск команды по URL из интерфейса команд;
- `find` — поиск объекта по имени, классу или тексту в активном окне; `exact` включает точное совпадение;
- `readField` — чтение отображаемого значения поля;
- `writeField` — запись текстового значения с повторным чтением; boolean-поля и флажки пока не поддерживаются;
- `readTable` — попытка чтения строк поддерживаемой TestClient таблицы;
- `formContext` — сводка элементов текущей формы и, по запросу, найденных таблиц;
- `createSnapshot`, `compareSnapshot`, `listSnapshots`, `deleteSnapshot` — временные снимки и сравнение состояния формы в памяти TS-сервера;
- `uiLog` — запуск, завершение, пауза, продолжение и отмена записи UI-сценария TestClient;
- `act` — `click` или `activate` объекта.

Каждое действие принимает необязательные `timeoutMs` и `background`. Ссылки выдаются `overview`, `find`, `commandInterface` и `formContext`; каждая из этих операций обновляет набор ссылок, а `executeCommand` очищает ссылки старого окна. `createSnapshot` и `compareSnapshot` сохраняют текущий набор ссылок. `find` всегда возвращает список совпадений; для чтения или действия передаётся конкретная ссылка из результата. Отсутствующие или устаревшие ссылки завершаются структурированной ошибкой.

Чтение таблицы выбирает все строки, считывает отображаемые значения и по возможности восстанавливает исходное выделение. На платформе без подтверждённого количества строк пустой или одноэлементный ответ консервативно помечается `complete: false`; ошибки декодирования и обрезанные ответы тоже не превращаются в достоверную пустую таблицу. `selectionRestored: false` указывает, что исходное выделение восстановить или подтвердить не удалось.

`readTable` проверена в реальном TestClient 8.3.27.1859 на временной EPF с двумя различимыми строками: обе строки прочитаны, ответ помечен полным, исходное выделение восстановлено. Причина первоначального отказа была в fixture: колонки таблицы были заданы неверными дочерними `<TableColumn>`; после замены на `InputField` внутри `Table` чтение сработало. В fixture также были `SelectionMode=MultiRow` и `HeightInTableRows=4`, но необходимость этих параметров отдельно не проверялась. Это подтверждает указанную форму и версию платформы, но само по себе не проверяет каждый вид таблиц и версию TestClient. Ошибки TestClient (включая `unsupported_element_type`) передаются как `NATIVE_OPERATION_REJECTED`, а не как пустой список. `formContext` с `includeTables: true` также возвращает ошибку, если чтение одной из таблиц отклонено. Значения колонок `EditField`, вложенных в `Table`, читаются через результат `readTable`; отдельный `GET_EDIT_TEXT` для таких колонок TestClient отклоняет.

Snapshots — состояние в памяти процесса расширения, а не сохранённые данные 1С; они исчезают при перезапуске TS-сервера. `createSnapshot` принимает `includeTables`, `maxDepth`, `maxNodes` и `maxRows`; выбранные параметры захвата хранятся вместе со снимком, а `compareSnapshot` повторяет их автоматически. `formContext` и snapshots отражают только доступные через протокол значения. `uiLog.finish` возвращает текстовую запись, если TestClient передал её в ответе.

## Транспорт и ошибки

Реализация протокола живёт в TypeScript TCP-клиенте и использует отдельный набор frame codec, сериализованный доступ к единственному сокету и ограничение времени на handshake/каждую команду. Timeout/отмена во время чтения ответа закрывает соединение: продолжать обмен после частичного кадра небезопасно. Если запрос на запись/действие уже отправлен, ответ помечает результат как неопределённый (`FORMS_OPERATION_IN_DOUBT`), так как внешнее действие могло завершиться.

Ошибки подключения, закрытия, таймаута, повреждённого кадра и отказа TestClient преобразуются в понятный результат Agent API. После разрыва канал помечается отключённым; продолжить можно новым `forms.start`.

## Лицензия и ограничения

Поведение сверяется с публичными сценариями и описанием методов [ROCTUP/1c-testpilot](https://github.com/ROCTUP/1c-testpilot), распространяемого под AGPL-3.0. В репозиторий MIT не переносятся исходники, тесты или сгенерированные файлы этого проекта. Реализация кода, тестов и внутренних контрактов CDT 41 написана самостоятельно.

Рабочая локальная среда проверена на платформе 1С 8.3.27.1859; совместимость с другими версиями не заявляется. Native screenshot — отдельный захват окна ОС: он работает только на Windows и только для локального TestClient с однозначным PID и видимым окном. Он не использует снимок из протокола формы и не управляет удалённым клиентом.

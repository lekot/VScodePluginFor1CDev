# Нативное управление тест-клиентом 1С

## Назначение

Нативный backend подключается по TCP к уже запущенному тонкому клиенту, стартовавшему с `/TESTCLIENT -TPort <port>`. Он работает независимо от браузерной сессии и сам не запускает и не останавливает процессы 1С или информационную базу. Действия формы могут менять данные открытой базы, поэтому подключайте подходящий тестовый клиент и учитывайте побочные эффекты своих действий.

Текущие web-сценарии остаются совместимыми: у `agent.forms.start` параметр `driver` по умолчанию равен `web`; `url` и `dbPath` доступны для web. Для `driver: "native"` обязателен `port`, `host` по умолчанию `127.0.0.1`, `platformVersion` необязателен. Запуск web и native использует общий lifecycle `forms.status` / `forms.stop`; остановка native соединения закрывает только сокет.

`agent.forms.exec` и `agent.forms.shot` относятся только к web backend. При активном native backend они возвращают понятную ошибку о несовместимости backend, не пытаясь запускать браузер.

## Native Agent/MCP API

Новый `agent.forms.native` и MCP tool `cdt_forms_native` используют обязательный `action` из дискриминированного набора:

- `overview` — активное окно и дерево доступных объектов формы;
- `find` — поиск объекта по имени, классу или тексту в активном окне; `exact` включает точное совпадение;
- `readField` — чтение отображаемого значения поля;
- `writeField` — запись текстового значения с повторным чтением; boolean-поля и флажки пока не поддерживаются;
- `act` — `click` или `activate` объекта.

Каждое действие принимает необязательные `timeoutMs` и `background`. Ссылки на объекты выдаются `overview`/`find` и действуют до следующего вызова любого из этих действий или до отключения сессии. `find` всегда возвращает список совпадений; для чтения или действия передаётся конкретная ссылка из результата. Отсутствующие или устаревшие ссылки завершаются структурированной ошибкой.

Чтение таблиц, snapshots и TestClient UI log пока не входят в доступный action union. Они будут добавлены после проверки основного протокола на локальной платформе.

## Транспорт и ошибки

Реализация протокола живёт в TypeScript TCP-клиенте и использует отдельный набор frame codec, сериализованный доступ к единственному сокету и ограничение времени на handshake/каждую команду. Timeout/отмена во время чтения ответа закрывает соединение: продолжать обмен после частичного кадра небезопасно. Если запрос на запись/действие уже отправлен, ответ помечает результат как неопределённый (`FORMS_OPERATION_IN_DOUBT`), так как внешнее действие могло завершиться.

Ошибки подключения, закрытия, таймаута, повреждённого кадра и отказа TestClient преобразуются в понятный результат Agent API. После разрыва канал помечается отключённым; продолжить можно новым `forms.start`.

## Лицензия и ограничения

Поведение сверяется с публичными сценариями и описанием методов [ROCTUP/1c-testpilot](https://github.com/ROCTUP/1c-testpilot), распространяемого под AGPL-3.0. В репозиторий MIT не переносятся исходники, тесты или сгенерированные файлы этого проекта. Реализация кода, тестов и внутренних контрактов CDT 41 написана самостоятельно.

Поддерживаемые версии 1С объявляются только после успешного сквозного прогона на соответствующей платформе. Нативный screenshot API пока не является частью этого контракта: `forms.shot` остаётся web-only.

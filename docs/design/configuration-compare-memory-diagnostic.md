# Диагностика памяти сравнения конфигураций

## Назначение

[`scripts/benchmark-configuration-compare-memory.cjs`](../../scripts/benchmark-configuration-compare-memory.cjs) — отдельная диагностическая утилита для одного ограниченного прогона сравнения `FormatSamples/uh` с самим собой. Она использует уже собранные CommonJS-файлы из `out` и не запускает сборку. По умолчанию сбор прекращается после завершения обоих manifest-этапов; раньше этого момента его может остановить порог памяти. Вариант `--stop-after hydration` задаёт более позднюю контрольную точку.

Запуск из корня репозитория:

```text
node scripts/benchmark-configuration-compare-memory.cjs
```

Параметры `--build-root <path>`, `--report <path>` и `--stop-after manifests|hydration` позволяют выбрать каталог собранных файлов, имя отчёта и контрольную точку. Отчёт записывается только непосредственным файлом в `suite-reports`; существующий файл не перезаписывается. Перед сравнением утилита фиксирует Node.js version и SHA-256, размер и mtime целевых собранных JS-файлов.

## Ограничения и чтение отчёта

Worker ограничен old-space 768 MiB, порогом диагностической отмены 512 MiB heap used, RSS 1 GiB, временем 180 секунд и отсутствием heartbeat 45 секунд. До sampling выполняется попытка V8 GC. Sampling использует интервал 256 KiB; отчёт содержит компактные call stacks и `sampledSelfBytes`, но не heap snapshot или dominator-анализ. Это оценка объёма sampled self-size, а не точный retained size и не объём всех выделений. Отчёт ограничен 128 KiB.

Статус `diagnostic-stopped` означает контролируемую отмену диагностического прогона. Он не означает завершение полного сравнения. В частности, отменённые manifest-стадии отображаются как неуспешные из-за ошибки отмены. Фаза и счётчики показывают, какие этапы успели завершиться.

## Фактический прогон 2026-11-26

Отчёт: [`configuration-compare-memory-1795732095314.json`](../../suite-reports/configuration-compare-memory-1795732095314.json).

- `FormatSamples/uh` сравнивался сам с собой на Node.js `v24.14.0`; worker завершился с `diagnostic-stopped`, exit code 0 за 114.3 секунды.
- Оба metadata-индекса завершились: по 50,217 identities каждый. На фазе `inventory`, до завершения обоих manifest и до hydration, сработал порог heap: 543,928,736 B (512 MiB threshold). Оба manifest-вызова были отменены; hydration и BSL-сравнение не выполнялись.
- Максимальный наблюдённый RSS составил 695,898,112 B; лимит RSS и wall-time не достигнуты. Ошибки OOM не было.
- Профиль сообщил суммарно 461,014,208 B `sampledSelfBytes`. Крупнейший стек связан с `path.normalize` из обхода manifest (144,717,088 B); следующий крупный стек связан с `buildOwnerIndex` (39,599,968 B).

Это один диагностический прогон, а не сравнительный benchmark. Sampled stacks дают направления для дальнейшего исследования, но не устанавливают единственную или окончательную причину роста памяти. Профиль не покрывает hydration и BSL-анализ; выводы об этих фазах из этого отчёта делать нельзя.
